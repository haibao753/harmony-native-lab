# AlgoLab 1.1.0 — Memory Explorer（开发预览）

**Release line:** 1.1  
**App versionName:** `1.1.0`  
**App versionCode:** `1100000`  
**Base:** AlgoLab 1.0.0, merged to `main`  
**Platform:** HarmonyOS Stage / ArkTS / ArkUI  
**Target:** HarmonyOS API 26; MatePad Pro 13.2

## What changed

### 1. Symbolic memory inspector

- Displays the `head` reference.
- Shows every node's symbolic object ID, `data`, and `next` reference.
- Shows reachability from `head`, cycle entry, and shared-successor information.
- Selecting a memory record selects the matching node on the canvas.
- Explicitly labels `N1`, `N2`, etc. as teaching object IDs, not real process addresses.

### 2. Code-to-structure navigation

- Clicking a generated allocation line selects its node.
- Clicking a `next` assignment selects the source node and highlights the matching pointer edge.
- Clicking the `head` assignment selects the head node.
- Clicking a `delete` line selects the object being released.
- The selected source line is highlighted in the code panel.

### 3. Canvas clarity

- Nodes display a `HEAD` marker when they are the current list entry.
- The memory inspector and C++ inspector are mutually exclusive, docked side panels; neither covers the canvas.
- The workspace adopts the Soft Precision visual language: warm off-white surfaces, graphite typography, restrained terracotta accents, and subtle matte depth.
- The C++ inspector replaces the earlier floating panel. Syntax highlighting, line navigation, annotation visibility, and font controls remain; annotations now sit below each source line.

## Preserved from 1.0

- Node creation, integer editing, moving, next linking/disconnecting, and head selection.
- Cycle, reachability, unreachable-node, and shared-successor analysis.
- Undo/redo.
- Deterministic read-only C++ generation.
- Syntax highlighting, line numbers, Chinese annotations, annotation toggle, font controls, and code-to-canvas navigation. The floating panel is replaced by a docked inspector.

## Verification status

This is a development preview on branch `feat/algolab-1.1-memory-explorer`. Source-level unit tests have been added for memory snapshots, cycle/shared-reference flags, and generated code-line mappings.

**Not yet verified:** ArkTS compilation in DevEco Studio, HAP packaging, or device behavior on MatePad Pro 13.2. GitHub source updates and static inspection do not substitute for a target-SDK build or real-device test.

## Manual acceptance checklist

1. Create three nodes with values 10, 20, and 30.
2. Connect N1 → N2 and leave N3 unreachable.
3. Open Memory View; confirm `head = &N1`, N1.next = &N2, and N3 is marked unreachable.
4. Select N2 in Memory View; close the panel and confirm N2 is selected on the canvas.
5. Create a cycle N2 → N1; confirm the memory panel identifies a cycle and its entry.
6. Open C++; click the `node1->next = node2;` line and confirm the N1 → N2 edge is highlighted.
7. Click the head assignment and an allocation line; confirm the corresponding node is selected.
8. Toggle between Memory View and C++ and confirm the two overlays do not overlap.
9. Recheck 1.0 code formatting: left alignment, preserved indentation, default 14vp font, 12vp Chinese annotations, annotation toggle, and compact font controls.

## Known limitations

- The memory inspector is a symbolic teaching model, not a debugger or a view of real process memory.
- C++ preview remains read-only; there is no built-in C++ compile/execute engine.
- Local experiment persistence is not included.
- Pointer creation still uses select-source then select-target, not direct port dragging.
- Latest UI changes require a DevEco rebuild and MatePad regression pass before release.
