## Product direction

Alpha 2 prioritizes understanding the linked list over adding more input modes. It continues from the 1.1 Memory Explorer baseline and keeps the scope on one data structure: the singly linked list.

The earlier Alpha 1 dual-input direction is not the focus of this iteration. Freehand drawing, complex ink management, and stylus-first node manipulation are intentionally excluded.

## What's included

### 1. Linked-list learning path

Seven focused topics are available:

1. Node structure: `data` and `next`
2. `head` as the entry reference
3. Pointer assignment through `next`
4. Traversal with `current`
5. `nullptr` and termination
6. Cycle detection
7. Reachability from `head`

Each topic includes a concept explanation, key point, common misconception, and an experiment to perform on the canvas.

### 2. Step-by-step traversal playback

The current linked-list document is converted into a deterministic, read-only trace:

- initialize `current = head`;
- check the loop condition;
- read `current->data`;
- advance with `current = current->next`;
- finish at `nullptr`, or stop when an already visited node is encountered.

The trace is generated from the current model and generated C++ source. It does not modify the document and does not execute C++.

### 3. Prediction and feedback

Before advancing, the learner answers a question about the current step. The workbench shows whether the prediction is correct and explains the underlying reason. Learners can move backward and restart the trace. Continuous playback can be paused at any time; after pausing, the learner can return to prediction-driven single-step practice.

### 4. Synchronized views

Each step updates the same presentation state:

- active node on the canvas;
- active pointer edge when advancing through `next`;
- `current` and visited-node summary;
- matching C++ source line;
- matching memory record when the Memory inspector is opened.

Editing the linked list, undoing, or redoing clears the old trace. The learner must regenerate it from the new document.

## Preserved from 1.1

- Single-linked-list node creation and integer editing
- `head` and `next` editing
- Node movement independent of pointer relationships
- Reachability, cycle, and shared-successor analysis
- Undo/redo
- Symbolic memory inspector
- Deterministic C++ generation, syntax highlighting, annotations, and code-to-canvas links

## Manual acceptance checklist

1. Open the Teaching Workbench and navigate all seven linked-list topics.
2. Create N1 → N2 → N3 and start traversal playback.
3. Confirm each step updates `current`, visited nodes, canvas selection, pointer-edge highlight, and C++ line.
4. Answer a prediction correctly and incorrectly; confirm both paths provide a reason.
5. Move backward and restart; confirm the trace returns to its initial state.
6. Open Memory and C++ inspectors from the teaching panel; confirm the selected node/line remains synchronized.
7. Edit a node or pointer while a trace exists; confirm the stale trace is cleared.
8. Create a cycle; confirm playback stops at the repeated node instead of looping indefinitely.
9. Start with `head = nullptr`; confirm the trace explains why the loop body is skipped.
10. Confirm teaching playback does not modify the linked-list document or undo/redo history.

## Known limitations

- Only linked-list concepts are included; other data structures are intentionally out of scope.
- Playback is a model-derived teaching trace, not a real C++ interpreter or debugger.
- The trace currently focuses on traversal and cycle stopping; insertion/deletion algorithm animations are not included.
- Local persistence and native C++ execution remain out of scope.
- Full stylus/ink interaction is not part of Alpha 2.
