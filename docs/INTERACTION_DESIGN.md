# AlgoLab 交互设计（Interaction Design）

- 版本：v0.1
- 对象：HarmonyOS NEXT 平板，优先横屏使用
- 设计目标：让结构本身成为可直接操作的对象；避免复杂工具栏和重复建设笔记能力。

## 1. 信息架构

v0.1 只保留一个主要工作空间：

- **主画布：** 节点、连接线、head 标记和状态提示。
- **轻量浮动工具：** 新建节点、撤销、重做、适配画布。
- **上下文操作：** 选中节点或连接后才出现编辑、连接、断开、删除等操作。
- **内存视图：** 用户主动打开后显示节点字段、模拟地址和引用关系。
- **代码抽屉：** 默认收起；展开后展示生成的 C++ 代码。
- **状态提示：** 以非阻塞方式提示环、不可达节点、共享后继等情况。

不设置常驻课程侧栏、笔记区、浏览器区或 AI 聊天区。

## 2. 画布视觉规则

- 节点卡片包含整数值和明确的 next 连接端口。
- head 使用独立标记，不能与普通 next 箭头混淆。
- null 连接以明确的空端点/空状态表达。
- 节点位置只负责空间布局；连接关系由逻辑字段决定。
- 节点被选中、连接被预览、环路和不可达节点应有不同且可区分的视觉状态。
- 不依赖颜色单独传达语义；同时使用线型、图标、标签或轮廓。
- 画布缩放时，节点文字和交互热区需要保持可读、可操作。

## 3. 手指与手写笔交互

所有手势均需在实际设备上验证，以下是产品设计目标，不代表目标设备的每个输入能力已完成验证。

| 输入 | 预期行为 | 设计约束 |
|---|---|---|
| 手指点击节点 | 选中节点，显示上下文操作 | 不立即执行破坏性动作 |
| 拖动节点主体 | 改变节点画布位置 | 不改变 next 逻辑关系 |
| 拖动 next 连接端口 | 预览一条待建立的连接 | 目标节点高亮；松手确认 |
| 在有效节点上松手 | 建立或替换 next 连接 | 若原连接会被替换，给出清楚反馈 |
| 在空白处松手 | 取消连接预览 | 不自动创建隐含节点 |
| 点击连接线 | 选中连接 | 提供断开/定位操作 |
| 双指拖动 | 平移画布 | 不移动节点 |
| 双指捏合 | 缩放画布 | 缩放中心尽量跟随手势中心 |
| 点击空白区域 | 取消选择 | 不清除结构 |
| M-Pencil 精确点选/轻量标记 | 可选的精细选择或短注释 | 不作为创建、移动全部节点或管理复杂笔迹的前提 |
| 撤销/重做 | 回退/恢复结构或布局命令 | 历史状态可预测 |

不建议把“双击空白处新建节点”作为唯一创建方式，以免与系统或画布手势冲突。v0.1 使用明确的“添加节点”操作，再把节点放到画布中。

### 输入优先级

- 手指：选择、平移、缩放和一般拖动。
- M-Pencil：可选的精确点选或轻量标记/批注，不承担全节点操控或自由绘图。
- 不要求手写笔压力、悬停或特殊按钮作为核心功能前提；若使用这些能力，必须先确认目标设备和 SDK 支持情况。

## 4. 关键交互流程

### A. 创建节点

1. 用户点击“添加节点”。
2. 画布出现一个新节点，初始值可编辑。
3. 节点被选中，焦点进入数值编辑。
4. 确认后节点保留在画布；取消则撤销创建。

### B. 建立 next 连接

1. 用户从节点 A 的 next 端口开始拖动。
2. 画布显示连接预览。
3. 指针进入节点 B 的有效目标区域时，B 高亮。
4. 松手后提交 A.next = B。
5. 若 A 原本指向其他节点，显示替换结果，并允许撤销。
6. 画布、内存视图、状态分析和代码映射一起更新。

### C. 断开连接

用户选中连接线并选择“断开”，或将 next 端口拖向明确的 null 目标。不要要求用户把线拖到任意空白处来猜测断开语义。

### D. 删除节点

- 删除前检查是否有 head 或其他节点引用它。
- 显示会受影响的引用关系。
- 用户确认后执行删除；所有被删除或被断开的关系形成一个可撤销命令。
- 不允许留下指向不存在节点的悬空模型引用。

### E. 设置 head

- 用户通过节点上下文操作“设为 head”，或拖动 head 标记到节点。
- head 是独立根引用，不等同于节点位置或第一条边。
- 可将 head 设为空，用于观察无入口的结构。

## 5. 三种同步视图

### 结构视图

展示节点、next 箭头和 head。视觉布局与逻辑关系分离。

### 内存/字段视图

每个节点展示：
- 教学对象标识（例如 N1，而非伪造的真实内存地址）；
- data 整数值；
- next 字段指向的对象标识或 nullptr。

如果展示十六进制样式的模拟地址，必须明确标注“模拟地址”，并确保它只是稳定的教学标签，不暗示真实运行时布局。

### C++ 代码视图

- 默认收起。
- 由当前结构模型确定性生成。
- 代码行映射到节点创建、字段赋值、head 设置等模型元素。
- 点击代码行时高亮对应元素。
- 结构变化后自动重新生成，并可展示简短差异。
- v0.1 代码只读，不允许任意编辑后声称可以无损同步回画布。

## 6. 渐进揭示

默认只展示结构画布和必要操作。用户按需打开：
1. 字段解释；
2. 内存引用关系；
3. 对应 C++ 代码；
4. 更深入的语法解释。

提示应与当前操作有关，例如用户首次创建节点时解释“节点由 data 和 next 两个字段组成”，而不是一开始展示一整页术语。

AI 若在后续版本接入，应由用户主动调用或在明确卡点时提供建议；不能持续弹窗打断实验。

## 7. 状态与反馈

至少识别以下状态：

- 空结构；
- head 为空；
- 正常从 head 可达的链；
- 孤立/不可达节点；
- next 指向 nullptr；
- 存在环；
- 多个节点指向同一后继（共享后继，不是典型线性链表）；
- 删除操作影响现有引用。

反馈应说明发生了什么以及为什么重要，不要简单显示“错误”。例如：“从 head 出发无法到达节点 N3”，而不是只显示红色警告。

## 8. 平板布局与系统协作

- 横屏优先，主画布占据大部分空间。
- 代码和内存视图采用可收起抽屉或覆盖面板，不长期挤压画布。
- 在窗口变窄时重新布局控件；核心画布仍可平移和缩放。
- 适配系统分屏/多窗口，不自行模拟系统多任务。
- 不实现笔记编辑、PDF 标注、网页浏览或系统级手写识别替代品。
- 可评估导出画布图片并使用系统分享能力，让用户转入华为笔记；具体分享 API 和跨应用行为待目标 SDK 验证。
- 不假设可直接操控华为笔记内部文档或私有数据。

## 9. 可用性与安全

- 所有结构修改均可撤销/重做。
- 拖动预览与最终提交状态清楚区分。
- 破坏性操作需要确认或可立即撤销。
- 连接目标有足够大的命中区域。
- 键盘输入可用于编辑整数值，但不要求用户使用键盘完成核心操作。
- 提供适当的无障碍标签；颜色不是唯一状态编码。
- 动画可关闭或减少，避免影响理解和性能。

## 10. 原型验收任务

邀请第一次使用的学习者，在不观看教程的情况下完成：
1. 创建值为 10、20、30 的三个节点；
2. 将它们连接成一条链；
3. 移动中间节点的位置，但保持逻辑连接不变；
4. 断开一条连接并撤销；
5. 建立一个环并找到状态提示；
6. 展开内存视图，说明 data 与 next 的区别；
7. 展开 C++ 视图，定位某条连接对应的赋值语句。

记录完成时间、误操作、求助次数，以及用户能否解释“移动节点”和“改变指针”的区别。


## 11. 1.2 Alpha 2：教学工作台与逐步演示

### 工作台入口

- 教学工作台由主页面顶部的单一入口打开；默认画布仍是主要实验区。
- 右侧教学面板提供七个单链表知识点：节点、head、next、遍历、nullptr、环和可达性。
- 选择知识点后，显示概念、关键点、常见误区和动手任务；内存视图与 C++ 视图由教学面板按需切换。

### 遍历步骤

1. 以当前文档的 `head` 和 `next` 关系生成只读轨迹，不重置或覆盖用户数据。
2. 每一步展示动作标题、原因说明、`current` 当前指向、已访问节点和对应 C++ 语句。
3. 画布同步高亮当前节点或刚经过的指针边；代码行高亮同步更新；打开内存视图时，当前节点同步选中。
4. 用户先回答预测题，收到正确/错误反馈及原因后，才能进入下一步；允许回退和重新演示。
5. 正常链表在 `current == nullptr` 时结束；遇到已访问节点时明确显示环检测结果。
6. 任何结构编辑、撤销或重做都会使旧轨迹失效，用户需重新开始。

### 手写笔边界

M-Pencil 不作为 1.2 Alpha 2 的核心功能依赖。后续如有明确教学价值，只评估精确选择或轻量标记/批注；不增加自由绘图、全节点手写操控、复杂笔迹管理或双输入模式堆叠。

### 验收重点

- 初次使用者能否说清 `data`、`next`、`head` 和 `current` 的区别；
- 能否预测每一步 `current` 的目标节点；
- 能否解释为什么尾节点的 `next` 是 `nullptr`，以及环为什么不会自然结束；
- 画布、内存、代码和步骤是否始终指向同一个节点/边/语句；
- 教学演示是否不改变用户原始链表。
