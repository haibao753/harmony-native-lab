# 架构约定

## 基本原则

- **原生优先**：ArkTS + ArkUI + Stage 模型。
- **按 API 能力设计**：所有系统 API 以项目实际 SDK 文档与编译器提示为准。
- **模块边界清楚**：页面、领域逻辑、数据访问和平台能力分层。
- **本地优先**：核心编辑流程不应依赖网络；同步与 AI 能力作为可选服务。
- **可验证**：不把未经构建的伪代码描述为可运行实现。

## 建议分层

```text
UI（ArkUI 页面、组件、主题）
        ↓
Application（页面状态、用例、协调逻辑）
        ↓
Domain（数学对象、文档模型、规则）
        ↓
Data（本地存储、导入导出、远程数据源）
        ↓
Platform adapters（HarmonyOS 系统 Kit）
```

这是一种逻辑分层建议。实际目录结构应以 DevEco Studio 生成的工程模板为基础，再逐步演进。

## 首个应用的边界

Math Workspace 首期聚焦：
- 工作区与文档列表；
- 数学内容画布；
- 公式和推导步骤的数据模型；
- 本地保存与恢复。

AI 推导、OCR、手写识别、跨设备同步、复杂 3D 可视化均作为后续独立能力，不在未验证前写入首期完成范围。

## 设计决策记录

重大技术选择请在 PR 或单独 ADR 中说明：背景、备选方案、决定、代价、验证方式与回滚方案。
