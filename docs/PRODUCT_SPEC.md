# AlgoLab 产品需求文档（Product Specification）

- 状态：v0.1 原型迭代中；首轮 MatePad 真机验证已完成，正在修复状态同步并准备第二轮验证
- 产品代号：AlgoLab
- 首发平台：HarmonyOS NEXT 原生平板应用
- 首要体验设备：Huawei MatePad Pro 13.2（2023 款，HarmonyOS 7.0.0；本机 DevEco SDK API 26）

## 1. 产品定义

**AlgoLab 是一款让学习者通过创造和操作数据结构，逐步理解其内存表示与 C++ 实现的交互式实验工具。**

它不是综合课程平台、笔记软件、浏览器、在线 IDE 或 AI 聊天应用。它专注解决一个具体断层：

> 学习者大致理解链表、树等结构的抽象形态，却不理解这些结构在计算机内存中如何表示，也不知道如何把图形关系翻译成 C++ 代码并理解代码运行结果。

AlgoLab 让学习者先动手创造，再逐步揭示结构语义、内存模型和代码表达。

## 2. 目标用户与核心问题

### 目标用户

- 对数据结构的抽象图示已有初步认识；
- C++ 基础不牢，尤其不熟悉类型、指针、动态内存和对象关系；
- 更容易通过空间操作、试错和即时反馈理解抽象概念；
- 使用平板，希望触控和手写笔成为主要交互方式。

### 核心问题

1. 图中的节点究竟对应什么 C++ 对象？
2. 指针字段保存的是什么，为什么箭头改变就意味着内存关系改变？
3. `Node`、`Node*`、`new`、`nullptr`、`->` 等语法分别表达什么？
4. 用户亲手改变结构后，如何得到与该结构一致的代码？
5. 如何通过安全、可解释的实验理解断链、空指针、环和不可达节点？

## 3. 产品原则

1. **先体验，后命名。** 不要求用户先读完术语和定义才开始操作。
2. **先由用户创造。** 画布和结构操作是主要入口，不以课程目录或代码编辑器为中心。
3. **图形、逻辑和代码必须一致。** 视觉位置不是指针关系；代码必须由明确的结构模型生成。
4. **渐进揭示。** 默认保持画布简洁；用户需要时才展开内存解释和代码。
5. **准确优先于炫技。** 不用误导性的动画或虚构的真实内存地址；所有抽象都明确标注。
6. **确定性优先于 AI 猜测。** 已识别的结构由确定性模型和代码生成器负责；AI 只作为可选辅助。
7. **不重复造轮子。** 笔记交给华为笔记，网页阅读交给系统浏览器，多窗口交给 HarmonyOS。
8. **离线优先。** 创建、编辑、分析、保存和代码预览不依赖 AI 服务或网络。

## 4. 核心学习闭环

1. **创造：** 用户在画布上创建节点、编辑值、设置 head、建立或断开 next 连接。
2. **观察：** 软件实时显示可达节点、孤立节点、环和连接关系。
3. **理解：** 用户按需打开内存视图，观察节点字段与指针引用；地址使用教学用标识，不冒充真实进程地址。
4. **翻译：** 软件将结构模型确定性地生成 C++ 代码，并建立代码行与画布元素之间的映射。
5. **实验：** 用户修改结构、观察状态变化，并比较代码差异。
6. **内化：** 后续练习逐渐隐藏生成结果，让用户预测或补全操作。

AI 不应持续打断探索，也不应替代用户的思考。可选 AI 能力包括解释当前状态、回答用户主动提出的问题，以及在未来辅助解释自由手绘草图。

## 5. v0.1 范围：单链表实验台

### 必须实现

- 一个以画布为中心的原生页面；
- 创建、删除和编辑整数节点；
- 设置或清除 head；
- 为节点的 next 字段建立、修改或断开连接；
- 拖动节点只改变画布位置，不改变逻辑连接；
- 平移、缩放画布；
- 选中节点或连接后显示轻量上下文操作；
- 显示从 head 可达的节点、不可达节点和环；
- 可选的内存/字段视图；
- 可收起的 C++ 代码面板；
- 结构修改后代码自动更新；
- 点击代码行时高亮对应节点或连接；
- 撤销、重做；
- 本地保存和恢复实验；
- 清晰展示无 head、空 next、断链、环等状态。

### v0.1 的交互边界

- 节点值先限定为整数，避免引入泛型和复杂类型系统。
- 每个节点只有一个 `next` 字段；head 是独立的根引用。
- 允许用户建立环和不可达节点，用于探索错误与边界情况。
- 如果出现多个前驱指向同一节点，标记为“共享后继/非典型线性链表”，不悄悄把它当作普通链表。
- 代码面板先只读；修改代码由画布操作驱动。
- 代码生成只支持 AlgoLab 明确定义的结构模型，不承诺把任意 C++ 代码反向解析成图形。

### v0.1 暂不实现

- 完整课程、题库、积分、签到、排行榜；
- 内置笔记、PDF 阅读器、浏览器或通用 AI 聊天；
- 任意自由手绘图形的自动识别；
- 任意 C++ 编辑、任意 C++ 反向解析；
- 在应用内直接编译和执行 C++；
- 账号体系、云同步、多人协作；
- 二叉树、图、排序和其他数据结构（待链表体验验证后扩展）。

## 6. 关键用户体验

### 首次进入

用户直接进入一个空画布，看到一个轻量提示：“创建一个节点，看看它在计算机中是什么。” 不先展示复杂课程导航。

### 创建与连接

用户创建节点并设置值；从一个节点的 next 连接点拖向另一个节点，松手确认连接。连接无效时提供明确反馈，不静默丢弃操作。

### 观察内存模型

用户打开“内存视图”后，看到每个节点的 data 和 next 字段。教学地址应标为“模拟地址”或“对象标识”，不得暗示它是运行时真实地址。

### 查看代码

用户主动展开代码面板。代码由结构模型生成；节点、字段、连接和代码行之间可以相互定位。代码更新时提供轻量差异提示，不强制弹窗。

### 错误探索

断开连接、制造环或删除仍被引用的节点时，软件展示状态变化和后果。默认允许可逆的实验，不用危险操作阻止探索；删除、断开等操作均可撤销。

## 7. 成功标准与验收

v0.1 不以页面数量或功能数量衡量成功。主要验收问题：

- 新用户能否在没有教程视频的情况下创建三个节点并连接它们？
- 用户能否区分“移动节点位置”和“改变 next 指针”？
- 用户能否从内存视图看懂 data 与 next 的区别？
- 生成的 C++ 是否与当前结构模型一致，且代码映射稳定？
- 用户能否通过撤销恢复误操作？
- 在 MatePad Pro 13.2 的横屏、竖屏和可用分屏宽度下，核心画布是否仍可操作？
- 断网时核心编辑、分析、保存和代码生成是否可用？

代码生成必须通过自动化快照/黄金测试；关键操作必须通过单元测试和真机交互测试。未实际构建、未真机验证的能力不得标记为完成。

## 8. 产品边界与风险

- 图形布局与逻辑引用必须分离，避免拖动节点意外改变结构。
- 指针连接需要清晰的拖拽起点、目标吸附和取消机制。
- 模拟地址只是教学抽象；真正的 C++ 运行时地址由编译器和运行环境决定。
- 生成代码需要处理环、不可达节点和内存释放，不能只生成看似正确的几行代码。
- 代码生成与真实 C++ 编译是两回事；v0.1 不声称可以在鸿蒙设备上编译运行。
- AI 手绘识别容易产生歧义，必须有用户确认步骤，且不作为结构模型的权威来源。
- HarmonyOS API、手写笔事件、系统分享和窗口行为均需按实际 SDK/API Level 与设备验证。

## 9. 后续阶段（不属于 v0.1 承诺）

- v0.2：更完整的 C++ 操作代码与逐步执行/内存变化解释。
- v0.3：用户主动触发的 AI 解释；评估受限的 C++ 云端编译执行。
- v0.4：自由手绘识别与确认式结构转换。
- 后续：在验证教学效果后，再考虑栈、队列、树和图。

## 10. 当前待决策问题

- 最终手写输入体验：自由手绘优先，还是结构化节点编辑优先？v0.1 先采用结构化编辑。
- 是否需要在 v0.1 导出 PNG？可作为低优先级，不阻塞核心闭环。
- 云端 C++ 执行的隐私、成本、隔离和服务可用性如何满足？先不纳入 v0.1。
